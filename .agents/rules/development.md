# Spec development rules

## Repository shape

- This git repo is a *vehicle*, not a module: it holds the published `spec`
  Bazel module (root `MODULE.bazel`) and the unpublished `spec_smoke_consumer`
  (`smoke/consumer/`). Never rename either module or invent a vehicle-wide
  version. `LEDGER.md` is the source of truth for which top-level directories
  belong here; `tools/ledger-check.sh` enforces it.
- Content is native. Do not `git subtree add` sibling fastverk repos, and do not
  create directories LEDGER.md lists as excluded (`platform`, `agents`, `rules`, …).
  `.agents/` (this plugin) is not the excluded `agents/` fleet; `agent/` is the
  Eve markup assistant, a product surface, not a coding-agent config.
- Each language lives where it already lives: Lean in `lean/`, SPARQL/TTL in
  `rdf/` and `corpus/`, Jena tooling in `java/` and `grounding/`, the Rust plugin
  in `services/spec/`, the Next.js console in `console/`, stdlib-Python tools in
  `tools/` and `conformance/`.

## Invariants that are easy to break

- **ARQ is the engine of record.** Gates run under Jena ARQ in Bazel. rdflib is
  a convenience for looking; never "fix" a gate so it passes under rdflib.
- **A pass over an empty population is not a pass.** Every authoring gate with a
  `.population.rq` must report the population it examined. When adding a gate,
  add its population query and a planted-defect fixture under `fixtures/` that
  the gate is shown to catch.
- **The corpus directory is the corpus.** `corpus/<name>/*.ttl` is exactly the
  `rdf_dataset` srcs. Fixtures, overlays and scratch TTL go in a subdirectory
  (`//tools/readmodel:corpus_is_the_corpus_test`).
- **Rungs are evidence, not intent.** Imported claims land at R0 with an
  `au:stalledOn`. Promotion carries `au:promotedBy`; never hand-set `au:rung`
  (`ladder-integrity.rq` refuses it).
- **The proposal log is append-only.** `logs/proposals.jsonl` is committed and
  gated; never rewrite it. Corrections are new proposals.
- **Proofs ratchet.** No `sorry`, no `native_decide`, and no axiom beyond
  `lean/axiom_baseline.txt` (`//lean:audit_proofs_test`).
- **Two implementations, one answer.** Safety rules that exist in Rust and in
  TypeScript share `conformance/*.json`; change the cases, not one side.
- Generated artifacts that are committed (`services/spec/ui/panels.binpb`, the
  `tier.ttl`, read-model payloads) are regenerated by their tool and checked by a
  diff/byte-equality test. Regenerate; do not hand-edit.

## Writing

- Comments in this repo explain *why* and record the measurement that justified
  a decision. Keep that style: say what failed, what was measured, what a check
  does not catch.
- Commit messages explain why. Never add tool or model attribution beyond the
  trailers the session requires.

## Verification

- Cheap, no Bazel: `bash tools/ledger-check.sh`,
  `python3 conformance/check_conformance.py`,
  `python3 tools/readmodel/check_wiring.py`,
  `python3 tools/readmodel/compile_panels.py`,
  `(cd console && pnpm install --frozen-lockfile && pnpm exec tsc --noEmit && pnpm exec vitest run)`.
- Bazel (CI flags: `--nohome_rc`): the `build` / `test` target lists in
  `.github/workflows/ci.yml`, plus `bazel test //lean:audit_proofs_test`.
- A change that touches the module's public surface (`rdf/*.bzl`, `rdf:authoring_vocab`,
  `MODULE.bazel` deps) must also pass the consumer smoke against this source:
  `(cd smoke/consumer && bazel --nohome_rc test //... --override_module=spec=$PWD/../..)`.
- Report skipped coverage honestly (e.g. the private-crates `//services/spec:spec_test`).
